# Static HTML Report — Instructions

## Overview

The static HTML report (`output/AWS_Cost_Dashboard.html`) is a fully self-contained, single-file
build of the React dashboard. It embeds all data, styles, and scripts — no server required.
It is the primary artefact shared with stakeholders.

---

## Refresh Workflow

**Whenever the underlying cost data changes** (new analysis run, service skill update, or
account scope change), both the dashboard data and the static HTML report must be regenerated
in sequence:

```bash
# Step 1 — Regenerate dashboard_data.json from the latest CSV outputs
#           (MUST run before the build — the build embeds this file into the HTML)
python generate_dashboard_data.py

# Step 2 — Rebuild the static HTML report (data is injected at build time)
cd dashboard
BUILD_MODE=singlefile npm run build
cp dist/index.html ../output/AWS_Cost_Dashboard.html
cd ..
```

> ⚠️ **Order matters**: `generate_dashboard_data.py` must run **before** `npm run build`.
> The Vite build reads `dashboard_data.json` and injects it as `window.__DASHBOARD_DATA__`
> directly into the HTML via the `injectDashboardData` plugin in `vite.config.ts`.
> This makes the report fully self-contained — it works when opened as a local `file://`
> with no server, no network requests, and no "Failed to fetch" errors.
>
> Or simply run: `bash refresh-data.sh`

## Report Versioning

The report carries a **semantic version** (`MAJOR.MINOR.PATCH`) stored in `REPORT_VERSION`.
The version is embedded in `dashboard_data.json` at build time and displayed in the report
header as a badge (e.g. `v1.2.0`) alongside the **"Last updated"** timestamp.

### Version file

```
REPORT_VERSION   ← plain text, single line, e.g. "1.2.0"
```

### When to bump the version

| Change type | Version component | Example trigger |
|---|---|---|
| Breaking schema change, major restructure | **MAJOR** | Rename/remove a field in the output schema; overhaul the dashboard layout |
| New feature or scope expansion | **MINOR** | New service skill added; new AWS account added to scope; new opportunity type; new dashboard panel |
| Data refresh or skill fix | **PATCH** | Re-running analysis against existing accounts; fixing a skill bug; correcting false positives |

### How to bump

Edit `REPORT_VERSION` manually before running the rebuild workflow:

```bash
# Example: bumping patch after a data refresh
echo "1.0.1" > REPORT_VERSION

# Then regenerate as normal:
python generate_dashboard_data.py
cd dashboard && BUILD_MODE=singlefile npm run build && cp dist/index.html ../output/AWS_Cost_Dashboard.html && cd ..
```

### What is displayed in the report

The report header shows two labels:

| Label | Source | Example |
|---|---|---|
| Version badge | `REPORT_VERSION` → `dashboard_data.json` → `report_version` | `v1.2.0` |
| Last updated | `generated_at` in `dashboard_data.json` (UTC timestamp set when `generate_dashboard_data.py` runs) | `Last updated: 25/03/2026, 09:26:23` |

When a stakeholder refers to a specific report, they should quote **both** — e.g.
*"I'm looking at v1.2.0, last updated 25 Mar 2026"* — so it is unambiguous which data snapshot
and which analysis logic version they are reviewing.

## File Locations

| File | Description |
|---|---|
| `REPORT_VERSION` | Semantic version source of truth — edit this before each release |
| `dashboard_data.json` | Intermediate JSON snapshot; regenerated by `generate_dashboard_data.py` |
| `output/AWS_Cost_Dashboard.html` | Final distributable; regenerated by the build step above |

## Summary: Full Regeneration Checklist

Run through this checklist after any of the following events:
- A service analysis script was re-run (new CSV in `output/`)
- A service skill (`.md` or `.py`) was updated
- An account was added to or removed from scope in `generate_dashboard_data.py`
- The dashboard UI was changed

```
[ ] Bump REPORT_VERSION if the change warrants it (see versioning rules above)
[ ] python generate_dashboard_data.py
[ ] cd dashboard && BUILD_MODE=singlefile npm run build
[ ] cp dashboard/dist/index.html output/AWS_Cost_Dashboard.html
[ ] Verify: open output/AWS_Cost_Dashboard.html and confirm version badge + timestamp are correct
```
