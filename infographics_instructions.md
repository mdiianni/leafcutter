# AWS Cost Analyser — Infographics & Frontend Instructions

## Overview

The dashboard is a **React + TypeScript** single-page application that reads from a local API
(served by the Python backend) and displays cost-saving opportunities, trends over time, and
per-service breakdowns in an attractive, motivating visual format.

The goal is to make cost savings *visible and compelling* — so both engineers and business
stakeholders can appreciate the effort and see the financial impact over time.

---

## Technology Stack

| Layer | Technology | Rationale |
|---|---|---|
| Framework | React 18 + TypeScript | Type safety, large ecosystem |
| Build tool | Vite | Fast HMR, small bundles |
| Charting | Recharts | Composable, React-native chart library |
| Styling | CSS Variables + CSS Modules | Theme switching via `data-theme` attribute, zero runtime overhead |
| Icons | Lucide React | Clean, consistent icon set |
| State management | React Context (theme) + useState | Lightweight, no extra deps |
| Data source | `public/dashboard_data.json` | Generated by `generate_dashboard_data.py`; fetched at startup |
| Animations | CSS transitions | Smooth hover/counter effects without extra dependencies |

> **Removed from original spec:** Tailwind CSS, shadcn/ui, Zustand, TanStack Query, Framer Motion, FastAPI backend.
> The dashboard is intentionally self-contained — no backend required. Run `npm run dev` in `dashboard/` to serve.

## KPI Cards (Top Row)

Each KPI card uses an **animated counter** (count-up on page load) and a **delta badge**
showing change vs. the previous run:

```
┌────────────────────────────────┐
│  💰 Total Monthly Savings       │
│                                │
│  $4,320                        │
│  ▲ +$320 vs last run           │  ← green delta if improving
└────────────────────────────────┘
```

Cards:
1. **Total monthly savings potential** (USD)
2. **Critical opportunities** (count + USD)
3. **High opportunities** (count + USD)
4. **Opportunities resolved since last run** (count + USD saved)
5. **Total resources scanned** (count)
6. **Annualised savings** (USD × 12)

## Charts

### 1. Savings by Service — Horizontal Bar Chart

- X-axis: USD / month
- Y-axis: Service name + icon
- Each bar coloured by service (consistent palette)
- Bars are **clickable** → navigates to `/services/:service`
- Tooltip shows: service name, opportunity count, total saving, top opportunity type

### 2. Severity Breakdown — Donut Chart

- Segments: CRITICAL (red), HIGH (orange), MEDIUM (yellow), LOW (green), DEPENDENCY (purple)
- Centre label: total opportunity count
- Clicking a segment filters the opportunities table below

### 3. Savings Trend — Area Line Chart

- X-axis: run dates (ISO, formatted as "MMM DD YYYY")
- Y-axis: estimated monthly savings (USD)
- Two series:
  - `Savings potential` (dashed line — what could be saved)
  - `Savings realised` (solid line — previous potential minus current potential = fixed)
- Tooltip shows: date, savings potential, savings realised, delta
- Shaded area between lines = the "savings gap still to close"

### 4. Opportunity Type Breakdown — Treemap

- Sized by estimated saving value
- Coloured by severity
- Labels: opportunity type + saving amount
- Clickable → filters opportunities table

## Opportunities Table (`/opportunities`)

Full filterable, sortable, paginated table of all opportunities.

Columns:
- Service (icon + name)
- Resource ID / Name
- Opportunity Type
- Severity (coloured badge)
- Current Cost ($/mo)
- Estimated Saving ($/mo)
- Saving %
- Recommendation (truncated, expandable)
- ⚠️ (dependency warning flag)

Filter controls:
- Service (multi-select)
- Severity (multi-select)
- Minimum saving (slider: $0–$1,000+/mo)
- Opportunity type (multi-select)
- Free-text search

Sorting: any column, ascending/descending.

Export button: downloads the current filtered view as CSV.

## Motivational Design Principles

1. **Show money, not jargon.** Lead with `$X/month` savings, not AWS resource IDs.
2. **Progress is visible.** A progress bar shows % of original savings potential that has been
   realised. Going from 0% to 65% is motivating.
3. **Celebrate wins.** When opportunities are resolved, a ✅ animation plays and the resolved
   item moves to a "Won!" section.
4. **Annualise everything.** Show `$52,000/year` alongside `$4,320/month` — the annual number
   is more impactful for business reporting.
5. **Dependency warnings are informative, not scary.** ⚠️ items are shown with clear next-step
   guidance, not blocked.
6. **Share-ready.** A "Generate Report" button produces a PDF-ready one-pager with charts and
   a summary table suitable for emailing to stakeholders.

## API Endpoints (Python FastAPI backend)

The frontend consumes these local API endpoints:

```
GET  /api/runs                         → List all analysis runs
GET  /api/runs/:run_id                 → Run details
GET  /api/runs/:run_id/opportunities   → All opportunities for a run
GET  /api/runs/:run_id/summary         → KPIs for dashboard cards
GET  /api/compare?run_a=:id&run_b=:id → Diff between two runs
GET  /api/services                     → List of services with opportunity counts
GET  /api/services/:service            → Opportunities for one service (latest run)
GET  /api/trend?account=:id&region=:r  → Time-series data for trend chart
POST /api/runs/trigger                 → Trigger a new analysis run (async)
GET  /api/runs/:run_id/status          → Poll run status
```

## Report Generation

A "Download Report" button on the dashboard:
1. Calls `GET /api/runs/:run_id/report` which returns a pre-rendered HTML page.
2. The frontend opens the HTML in a new tab; user prints to PDF.

The report includes:
- Cover: Account ID, region, date, total savings headline
- Executive summary: top 5 opportunities with saving amounts
- Per-service breakdown table
- Trend chart (if multiple runs exist)
- Full opportunities table sorted by saving descending
- Methodology notes and caveats

## Filtering, Sorting & Pagination

### Header Filters
Two filter controls live in the sticky header, applied globally to all charts and tables:

| Control | Type | Values |
|---------|------|--------|
| Group selector | `<select>` dropdown | All Groups + each unique group name |
| Env filter | Pill buttons | All Envs / DEV / STG / PRD |

- Selecting a group **and** an env applies both filters simultaneously (AND logic).
- Changing either filter resets any active account selection.
- Active env pill is highlighted with the env colour (blue=DEV, amber=STG, green=PRD).

### Account Summary — Sortable Columns
Clicking a column header toggles ascending/descending sort. Sortable columns:

| Column | Default sort | Indicator |
|--------|-------------|-----------|
| Account | alpha asc | ⇅ / ↑ / ↓ |
| Invoice/mo | numeric desc | ⇅ / ↑ / ↓ |
| Saving/mo | numeric desc *(default)* | ⇅ / ↑ / ↓ |
| Saving % | numeric desc | ⇅ / ↑ / ↓ |

Sorting resets to page 1 automatically.

### Account Summary — Pagination
- Default page size: **10 rows**
- Controls: « ‹ [1] [2] [3] › » (sliding window of 5 page numbers)
- Row count shown: e.g. "1–10 of 20"
- Pagination only renders when `total_accounts > PAGE_SIZE`

### Top Opportunities — Pagination
- Default page size: **25 rows**
- Same « ‹ [n] › » control pattern
- Recommendation text truncated at 60 chars; **more/less** toggle expands inline


### Top Opportunities — Sorting & Filters

**Sortable columns** (click header to toggle asc/desc):

| Column | Default sort |
|--------|-------------|
| Service | alpha asc |
| Resource | alpha asc |
| Type | alpha asc |
| Severity | severity order (CRITICAL → INFO) |
| Saving/mo | numeric desc *(default)* |

**Filter dropdowns** (in the card header, next to the title):

| Control | Options |
|---------|---------|
| Service | All Services + one per unique service in current view |
| Severity | All Severities + CRITICAL / HIGH / MEDIUM / LOW / DEPENDENCY / INFO |

- Filters and sorting are applied before pagination (filtered count shown in header).
- A **✕ Clear** button appears when any filter is active.
- Empty state row shown when no opportunities match the filters.
- Row expansion keys are stable across filter/sort changes.
