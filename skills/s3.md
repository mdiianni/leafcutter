# Skill: Amazon S3 — Cost-Saving Opportunities

## Service Overview

Amazon S3 costs accrue from storage, API requests, and data transfer. The principal levers are
**storage class optimisation**, **lifecycle policies**, and **eliminating unnecessary data**.

> ⚠️ **Important:** S3 buckets may contain millions of objects. We **must not** enumerate objects
> directly (e.g., `list_objects_v2`) as this incurs per-request costs at scale. Instead we rely on:
> 1. **S3 Storage Lens** metrics (if enabled)
> 2. **CloudWatch S3 bucket metrics** (free daily metrics)
> 3. **Bucket-level configuration** (lifecycle, versioning, replication, etc.)

---

## Data Collection

### AWS API Calls

```python
s3  = session.client("s3")
cw  = session.client("cloudwatch", region_name=region)

# List all buckets (account-level, not region-specific)
s3.list_buckets()

# Per-bucket configuration (parallelise with ThreadPoolExecutor)
s3.get_bucket_location(Bucket=bucket_name)
s3.get_bucket_lifecycle_configuration(Bucket=bucket_name)     # may throw NoSuchLifecycleConfiguration
s3.get_bucket_versioning(Bucket=bucket_name)
s3.get_bucket_tagging(Bucket=bucket_name)                     # may throw NoSuchTagSet
s3.get_bucket_intelligent_tiering_configuration(Bucket=...)   # may throw NoSuchConfiguration
s3.get_bucket_replication(Bucket=bucket_name)                 # may throw ReplicationConfigurationNotFoundError

# CloudWatch: BucketSizeBytes (daily metric, filter by storage class)
cw.get_metric_statistics(
    Namespace="AWS/S3",
    MetricName="BucketSizeBytes",
    Dimensions=[
        {"Name": "BucketName",   "Value": bucket_name},
        {"Name": "StorageType",  "Value": "StandardStorage"},  # repeat per storage class
    ],
    StartTime=now - timedelta(days=3),
    EndTime=now,
    Period=86400,
    Statistics=["Average"]
)

# Storage classes to query:
# StandardStorage, IntelligentTieringStorage, StandardIAStorage,
# OneZoneIAStorage, GlacierStorage, DeepArchiveStorage, ReducedRedundancyStorage

# CloudWatch: NumberOfObjects
cw.get_metric_statistics(
    Namespace="AWS/S3",
    MetricName="NumberOfObjects",
    Dimensions=[
        {"Name": "BucketName",   "Value": bucket_name},
        {"Name": "StorageType",  "Value": "AllStorageTypes"},
    ],
    ...
)
```

### Cache TTL
- Bucket configurations: **24 hours**
- CloudWatch storage metrics: **24 hours** (metrics update daily)

## Opportunity 1 — No Lifecycle Policy

**Severity:** 🟠 HIGH  
**Opportunity type:** `s3-missing-lifecycle`

**Detection logic:**
- Call `get_bucket_lifecycle_configuration`. If the call raises `NoSuchLifecycleConfiguration`,
  the bucket has no lifecycle policy.
- Applies to any bucket with `StandardStorage > 0 bytes`.

**Recommendation:**
> "Bucket '{bucket}' has {size_gb} GB in Standard storage and no lifecycle policy. Adding a
> lifecycle policy to transition objects to S3-IA after 30 days and Glacier after 90 days can
> reduce storage costs by 40–85%. Estimated saving: ~${saving}/month."

**Estimated saving calculation:**
```
standard_gb      = cloudwatch_BucketSizeBytes_Standard / 1e9
ia_transition_pct= 0.60   # assume 60% of objects are accessed < once a month
saving_per_gb    = price_standard - price_ia          # e.g. $0.023 - $0.0125 = $0.0105/GB
monthly_saving   = standard_gb * ia_transition_pct * saving_per_gb
```

## Opportunity 2 — Standard Storage with No Intelligent Tiering

**Severity:** 🟡 MEDIUM  
**Opportunity type:** `s3-intelligent-tiering`

**Detection logic:**
- Bucket has > 10 GB in `StandardStorage` AND no `IntelligentTieringStorage`.
- S3 Intelligent-Tiering automatically moves objects between Frequent and Infrequent Access tiers.
- Best for buckets with **unpredictable or mixed access patterns**.

**Recommendation:**
> "Bucket '{bucket}' has {size_gb} GB in Standard storage. Enabling S3 Intelligent-Tiering
> could reduce costs by 40–68% for infrequently-accessed objects. No retrieval fees apply
> when moving between tiers."

---

## Opportunity 3 — Versioning Enabled, No Lifecycle Rule for Non-Current Versions

**Severity:** 🟠 HIGH  
**Opportunity type:** `s3-versioning-cost`

**Detection logic:**
- `get_bucket_versioning` returns `Status = "Enabled"`.
- No lifecycle rule with `NoncurrentVersionExpiration` action exists.
- Non-current (stale) versions accumulate silently and are billed at full Standard rates.

**Recommendation:**
> "Bucket '{bucket}' has versioning enabled but no expiry rule for non-current versions.
> Add a lifecycle rule to expire non-current versions after 30–90 days to avoid paying
> indefinitely for replaced object versions."

---

## Opportunity 4 — Reduced Redundancy Storage Class in Use

**Severity:** 🟠 HIGH  
**Opportunity type:** `s3-rrs-deprecated`

**Detection logic:**
- `CloudWatch ReducedRedundancyStorage > 0 bytes`.
- RRS is deprecated — Standard offers lower cost and higher durability (11 nines).

**Recommendation:**
> "Bucket '{bucket}' still has data in the deprecated Reduced Redundancy Storage (RRS) class.
> Standard storage is now cheaper than RRS and offers higher durability. Migrate all RRS objects
> to Standard or S3-IA."

---

## Opportunity 5 — Cross-Region Replication (CRR) Without Lifecycle

**Severity:** 🟡 MEDIUM  
**Opportunity type:** `s3-crr-cost`

**Detection logic:**
- `get_bucket_replication` returns a replication configuration.
- No lifecycle policy on the **destination** bucket.
- CRR doubles storage costs if not managed.

**Recommendation:**
> "Bucket '{bucket}' has Cross-Region Replication enabled. Ensure the destination bucket has a
> lifecycle policy to manage replicated object costs. Without it, storage costs are effectively
> doubled for replicated data."

---

## Opportunity 6 — Empty Buckets

**Severity:** 🟢 LOW  
**Opportunity type:** `s3-empty-bucket`

**Detection logic:**
- `CloudWatch NumberOfObjects = 0` (or no data point → no objects ever stored).
- Bucket may be unused infrastructure.

**Recommendation:**
> "Bucket '{bucket}' appears to be empty. If it is no longer needed, consider deleting it to
> remove clutter and reduce the blast radius of future IAM misconfiguration."

---

## Opportunity 7 — Glacier Instant Retrieval vs Deep Archive Review

**Severity:** 🟢 LOW  
**Opportunity type:** `s3-archive-tiering`

**Detection logic:**
- Bucket has data in `GlacierStorage` (Glacier Flexible Retrieval) AND the objects have not been
  retrieved in the observation window.
- Glacier Deep Archive costs ~$0.00099/GB vs Glacier Flexible at ~$0.004/GB — a 4× difference.

**Recommendation:**
> "Bucket '{bucket}' has {size_gb} GB in Glacier storage. If objects are rarely or never
> retrieved, migrating to S3 Glacier Deep Archive could save ~${saving}/month."

## Notes

- **Never call `list_objects_v2`** on buckets in this tool. All size data must come from CloudWatch.
- Only report on buckets **in the target region** (filter by `get_bucket_location`).
- Tag-based filtering: skip buckets with tag `cost-analyser:ignore = true`.
- Some buckets may have S3 Storage Lens enabled at the org level — if available, prefer Storage
  Lens data as it is more accurate and updated daily at no extra cost.
